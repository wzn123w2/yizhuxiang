# 且坐 · 一炷香的时间（本地重建版）

名字取自殿里那支香：游戏里的香正好燃两分钟，**"再坐一炷香"**也就是这个游戏的时间单位。

参照 [sansatemple](https://sansatemple.com) 的玩法结构，在浏览器里重建的一间三维佛堂。
纯前端、无后端、无外部美术/音频资源 —— 场景和声音全部用代码生成。

**这一版是"骨架"，目标是先把这座山寺的操作手感对齐，然后我们一起慢慢改。**

## 跑起来

```bash
cd shanshi
npm install
npm run dev -- --host
```

- 电脑：`http://localhost:5173/`
- 手机：用终端打印的 `Network` 地址（同一 WiFi）

生产构建：`npm run build && npm run preview -- --host`

## 部署上线

部署形态是**一个 Node 进程**：同一端口既托管 `dist/` 静态页，也接 `/ws` 同修连线。
前端用 `location.host` 拼 ws 地址，所以换域名、上 HTTPS 都不用改代码。

```bash
npm ci && npm run build
PORT=8787 MAX_PLAYERS=12 node server/index.mjs
# 打开 http://<IP>:8787/ 就是完整应用；健康检查 /healthz
```

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | 8787 | 监听端口，平台注入的 `PORT` 可直接用 |
| `MAX_PLAYERS` | 12 | 一间法堂上限，与殿内 12 张坐垫对应 |
| `DATA_DIR` | `<仓库>/data` | 运行时数据目录（签筒记录与盐；旧名 `FEEDBACK_DIR` 仍兼容，Docker 里是 `/app/data`） |
| `FORTUNE_IP_DAILY` | 8 | 同一 IP 每天最多几支不同的签（防清缓存换签） |
| `DAY_OFFSET_MIN` | 480 | "一天"的分界，默认东八区（+480 分钟） |
| `WEATHER_CITY` | 北京 | 天气播报的城市名（只作显示） |
| `WEATHER_LAT` / `WEATHER_LON` | 39.9042 / 116.4074 | Open-Meteo 用的坐标 |

`deploy/` 里现成的模板：

- `deploy/Caddyfile` —— 反向代理 + 自动 HTTPS（**最省事，自动透传 WebSocket**）
- `deploy/nginx.conf` —— nginx 版，手写了 Upgrade 头与 90s read timeout
- `deploy/shanshi.service` —— systemd 守护（路径/用户按机器改）
- `Dockerfile` —— 多阶段构建，`docker build -t shansi . && docker run -p 8787:8787 shansi`

注意事项：

- **只能单实例**：玩家与坐垫状态都在内存里（`server/index.mjs` 的 `players` / `seats`），不能横向扩容、不能部署到 serverless
- 服务端每 20s 发一次 ping，反向代理的 `read_timeout` 必须大于这个值
- 想在国内托管需域名备案；先用 `http://<IP>:8787` 明文试玩也可以（微信内置浏览器能开）

## 佛乐（public/audio）

殿里有五首实录梵呗，顺序循环：`public/audio/*.m4a`。
源文件是 320 kbps 的 mp3，进仓库前用 `afconvert` 转成了 96 kbps 的 AAC（m4a），
39 MB 顶原先的 128 MB；人声、磬、铃都在，手机外放听不出差别。

| 文件 | 曲目 |
|---|---|
| `01-namo-amitabha.m4a` | 南无阿弥陀佛 · 李娜 |
| `02-heart-sutra.m4a` | 般若波罗蜜多心经 · 慧普法师 |
| `03-shakyamuni.m4a` | 释迦牟尼佛圣号 · 则旭法师 |
| `04-padmasambhava.m4a` | 莲花生大士心咒 · 菩提道一 |
| `05-great-compassion.m4a` | 大悲咒 · 般禅梵唱妙音组 |

播放层是 `src/audio/music.ts`：用 `<audio>` 而不是 Web Audio，理由写在文件头（分片缓冲、iOS 媒体通道、AudioContext 重建不打断）。

- 顺序在 `MUSIC_TRACKS` 里改；加曲子就把 m4a 丢进 `public/audio/`，再添一行
- 服务器对 `/audio/` 开了 `Range`（206）与长缓存，半小时的《大悲咒》能边下边听、能拖进度
- 佛乐在放时，合成的梵呗会整条让位（`Chant.setDuck`）；关掉佛乐就回来
- 音量、开关、下一首都在设置面板；静音和顶部「声音」按钮同一条口径，切后台自动暂停

曲子版权归各自演唱/演奏者，仅作个人清修使用，别拿去做商业分发。

## 天气与昼夜（按北京时间）

游戏的天空跟着**北京当天/此刻的天气**走，昼夜也改成按北京时间算（不再看访客本机时区）。

```
浏览器  ──GET /api/weather──▶  Node（缓存 10 分钟）
                                 ├─ t.weather.itboy.net（中国天气网数据，国内可直连）
                                 └─ api.open-meteo.com（WMO 天气码，境外可达）
```

两个源并行问，谁先回用谁；都失败就先给上一次的缓存（`stale: true`），
再没有就给"晴"，前端不会因为没网就没有天空。前端每 10 分钟 + 切回页面时刷新一次。

| kind | 天空 | 光照 / 雾 | 特效 |
|---|---|---|---|
| `clear` 晴 | 通透的蓝天 | 雾很薄、太阳最强 | 零星几缕云 |
| `partly` 晴间多云 | 蓝，带薄云 | 略柔 | 云量中等 |
| `cloudy` 多云 | 灰蓝 | 太阳减弱 | 成片云 |
| `overcast` 阴 | 灰 | 平光、雾稍浓 | 云盖满 |
| `fog` 雾 | 灰白 | 雾最浓 | 云压得低 |
| `rain` 雨 | 暗灰蓝 | 冷、暗 | 雨丝 + 庭院地面涟漪 |
| `snow` 雪 | 冷灰白 | 亮而冷 | 雪花 + 庭院/屋顶积雪 |
| `thunder` 雷雨 | 最暗 | 冷暗 | 同雨 |

实现分两块：

- `src/world/temple.ts`：`setWeather()` 把天气折进昼夜调色板（天空渐变、雾、太阳/环境光、
  灯笼与佛坛亮度），雪天另外淡入一层雪盖（庭院、台阶、屋顶、正脊）。
  殿内有屋顶，所以**殿内地面不积雪、不落雨**。
- `src/world/weather.ts`：云（贴地平线的 sprite，跟着相机走）、雨（LineSegments）、
  雪（Points）、涟漪（加法混合的水纹贴图，只在 `groundHeightAt < -0.5` 的庭院出生）。

调试：控制台 `__weather('snow')` 可强制切换，`__vfx()` 看粒子/涟漪数量。

## 求签（今日一签）

殿门口左手边立着签筒，进门就能看见；右上角常驻「求签」（今天还没求时带一个小金点）。
两处都能求，**同一天只会得到同一支签**。

### 一次是怎么算出来的

签不是"抽"完存下来，而是**算**出来的：

```
种子 = sha256(部署盐 | "fortune" | 日期 | 设备号)
种子 → 等级（上上/上/中上/中/中下，按 8/22/30/30/10 加权）→ 该等级里的一支
```

所以清 localStorage、换浏览器、刷新页面都换不到第二支签——"每天一次"靠的是
**抽不出第二个结果**，而不是把按钮变灰。落一条 `data/fortune.jsonl` 只为了
"今日已求 · 几点求的"和统计；就算记录丢了，签也不会变。

同一网络每天最多出 8 支不同的签（`FORTUNE_IP_DAILY`），防止换设备号刷签。

### 黄历部分

服务端按公历日期推算，随签一起返回：

- **干支日**：以 1949-10-01 甲子日为锚点，精确；
- **干支年 / 月**：立春与十二"节"取近似日期（误差约一天），够做日课；
- **农历**：用 `Intl` 的 chinese 日历，拿不到就略过这一行；
- **建除十二神**：由日支与月建推出来，并配一张宜 / 忌表；
- **冲煞 / 日主五行**：由日支、日干直接算。

这是山寺的"日课"，不作吉凶断语。

### 想改签文

二十四支签都在 `server/fortune.mjs` 的 `LOTS` 里，改 `verse`（七言四句）、
`read`（解签）、`today`（今日行止）即可；等级比例在 `GRADES`，宜忌在 `JIANCHU_RULES`。
改完重启服务就生效（前端不用重新构建）。

### 接口

```
POST /api/fortune   { "device": "..." }
  → { ok, first, drawnAt, almanac: {...}, lot: { no, grade, title, tag, verse, read, today } }
  429 { code: "network" }   同一网络今天签数已满
```

只收 `application/json`、拒跨站 `Sec-Fetch-Site`、按 IP 限频；
设备号只以加盐哈希落盘。

## 更新公告（每次发版弹一次）

首屏出现后弹一个「这次更新了什么」，只弹**没看过的**；关掉后把 id 记在本机存档里，下次不再弹。

**发版时只改一个文件**：`src/core/changelog.ts`，在 `CHANGELOG` 数组最上面加一条，`id` 换成没出现过的值：

```ts
{
  id: '2026-11-20.1',   // 换 id 就等于"有新公告"，建议 日期 + 序号
  date: '2026-11-20',
  title: '一句话概括这一版',
  items: ['改了什么', '修了什么', '加了什么'],
}
```

- 只弹"比本地记住的 id 更新"的条目；一次跳过好几版，会把这几版按条列出来。
- 没看过、或本地 id 已不在列表里（回滚过版本）→ 只弹最新一条，不会一上来砸一屏。
- 设置里的「更新公告」可以回顾最近 5 条，不算未读。
- 公告一律用 `textContent` 渲染：写 HTML 不生效，也不会被执行。
- 想强制所有人再看一次：把最新那条的 `id` 改一下（例如加 `.2`）即可。
- 弹窗在 `index.html` 的 `#notice`、样式在 `style.css` 的「更新公告」段，逻辑在 `main.ts` 的「更新公告」段。

### 两个关键设计

**1. 角色动画是"目标值 + 插值"，没有动画剪辑**

`Monk.setPose()` 只改一组目标角度（躯干前倾、手臂旋转、缩放），
`update()` 每帧朝目标插值。好处是切换姿态天然带过渡、不用做动画状态机，
坏处是做不了复杂的动作——够用，且改起来极快。

**2. 音源模块不缓存 AudioContext**

iOS / 微信内置浏览器切后台会销毁上下文，回来必须重建。
所以 `AudioHost` 独占生命周期，`Wind` / `Chant` 通过 `host.onRebuild()` 重新挂载。
`rebuild()` 里回调放在 `await unlock()` **之后**，否则新上下文还没 running，音源静默失败。

**3. 手机没声的几种常见原因（已分别处理）**

| 现象 | 原因 | 处理 |
|---|---|---|
| 苹果手机开着侧边静音键 | iOS 默认用 ambient 音频会话，Web Audio 跟着静音键一起静 | `armSession()`：iOS 16.4+ 设 `navigator.audioSession.type = 'playback'`；再挂一条无声循环 `<audio>`（44.1kHz/16bit/立体声，挂进 DOM），把会话顶到媒体通道 —— 微信的 WKWebView 里没有 audioSession API，只能靠这条老办法 |
| 切后台 / 锁屏 / 来电回来后彻底没声 | 上下文停在 `suspended`，iOS 还会给一个 `interrupted`，微信里这种情况 resume 基本无效 | `ensureAlive()` 处理这两种态，必要时 `rebuild()` 重建上下文；任何一次手势（`pointerdown` / `touchend` / `keydown`）都会重试 |
| 微信里点开了但没声 | WKWebView 要求「媒体元素 + Web Audio 音源」在同一次手势里各起一次真音，且媒体通道要先碰一下 JSBridge | `unlock()` 里 `armSession()`（含 `WeixinJSBridge.invoke('getNetworkType')`）与 `ping()` 同步执行；`resume()` 带 800ms 超时，避免把开门流程卡死 |
| 首次进来安静 | 首访默认静音 | 右上「开启声音」按钮；也可在设置里拖任意一档音量自动开声 |

排查口子：

- 设置面板里有「音频状态」一行和「试听 · 声音自检」按钮，手机上不用控制台也能看到
  `running / suspended / interrupted`、是否静音、iOS 的媒体通道有没有挂上、主输出峰值 dBFS。
- 构建时间也显示在设置底部：微信缓存很凶，先确认跑的不是旧包。
- 控制台 `await __audio()` 同样会返回上下文状态与三档总线峰值。
